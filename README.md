# Дневник калорий

Дневник калорий по фото. Делаешь снимок тарелки, а модель распознаёт блюда, оценивает вес порций и считает калории и БЖУ с разбивкой по ингредиентам. Приложение ставится на телефон как PWA (иконка на главном экране, открывается без браузерной строки).

- Вход по почте и одноразовому коду из 6 цифр, без паролей. Только по приглашению: открытой регистрации нет.
- Данные хранятся в SQLite на вашем сервере. Фото никуда не сохраняются: их уменьшают на телефоне, отправляют модели и после подсчёта выбрасывают.
- По умолчанию распознаёт GLM от [z.ai](https://z.ai) (`glm-4.6v`). Подойдёт и любой другой OpenAI-совместимый API с поддержкой картинок: OpenRouter, OpenAI, Gemini.
- Дневной лимит распознаваний на человека защищает ваш бюджет на API.

## Отметки «Туалет»

Включаются каждым для себя: «Настройки → Аккаунт → Отмечать походы в туалет». На экране «Сегодня» появляется карточка с кнопкой «+ Отметить»: одно нажатие — одна отметка с текущим временем. Нажми на время, чтобы исправить его или удалить отметку. Для прошлого дня отметка создаётся с текущим временем и сразу открывается для правки.

В «Отчёте» — блок «Туалет и еда» за последние 60 дней: сколько раз в среднем за день, максимум, сколько обычно проходит от еды до похода, и корреляция числа походов с калориями, весом еды и БЖУ в тот же день и накануне. Учитываются дни с записанной едой начиная с первой отметки. Выводы появляются от 7 дней данных.

## Время приёма пищи

У каждой записи хранится время, когда еду съели. В окне новой записи есть поле «Время»: по умолчанию — сейчас, а для фото из галереи — время съёмки из EXIF (с пометкой «по фото», если оно отличается от текущего больше чем на 10 минут). Под это время сам подстраивается завтрак/обед/ужин, пока его не выбрали вручную. В дневнике время показано рядом с названием приёма; нажми на него, чтобы исправить. От этого времени считается «от еды до туалета».

## Клетчатка, ярлыки и выгрузка

При распознавании модель оценивает клетчатку каждого ингредиента и ставит блюдам ярлыки из фиксированного списка (молочное, кофе, алкоголь, сладкое, жареное, острое, овощи, фрукты, цельнозерновое, бобовые и др.). Клетчатка показана в итогах дня, ярлыки и клетчатка участвуют в анализе «Туалет и еда». У записей, сделанных раньше, этих данных нет — они не считаются нулём, а просто не участвуют.

«Настройки → Аккаунт → Скачать данные (Excel)» — весь дневник одним файлом: лист «Дни» (итоги, клетчатка, число походов, средний тип стула, ярлыки), «Еда» (по строке на ингредиент) и «Туалет» (время, тип, часов после еды). Время — в часовом поясе телефона.

## Стек

Node.js 22, TypeScript, Fastify, better-sqlite3. Фронтенд — один HTML-файл и чистый JS без сборки. Всё работает в одном Docker-контейнере.

## Развёртывание

Понадобятся сервер с Docker, домен (или поддомен), указывающий на сервер, и ключ API модели.

```bash
git clone <адрес репозитория> kkal && cd kkal
cp .env.example .env
nano .env          # ADMIN_EMAIL и BASE_URL; остальное — в приложении
docker compose up -d --build
```

Откройте сайт, введите адрес из `ADMIN_EMAIL` и код из письма. Вы администратор.

Пока почта не настроена, можно задать в `.env` временный постоянный код `STATIC_LOGIN_CODE=123456` (6 цифр). Он работает только для `ADMIN_EMAIL`; после 10 неверных кодов за час вход для адреса блокируется на час. Уберите его, когда заработает почта.

Без него код можно взять из лога: `docker compose logs kkal | grep -A3 "Кому:"`. Ещё в лог при первом запуске пишется одноразовая ссылка администратора, на случай если почты нет совсем.

### HTTPS через nginx

Создайте `/etc/nginx/sites-available/diary.example.com`:

```nginx
server {
    listen 80;
    server_name diary.example.com;

    client_max_body_size 20m;     # фото; без этого — ошибка 413
    proxy_read_timeout 330s;      # модель может думать несколько минут

    location / {
        proxy_pass http://127.0.0.1:3010;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/diary.example.com /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d diary.example.com
```

### HTTPS через Caddy

Установка на телефон и безопасная cookie сессии работают только по HTTPS. Если Caddy установлен прямо на сервере, добавьте в `Caddyfile`:

```
kkal.example.com {
    reverse_proxy 127.0.0.1:3010
}
```

Если Caddy работает в Docker (например, вместе с n8n), уберите блок `ports` из `docker-compose.yml`, подключите сервис к сети Caddy и проксируйте по имени контейнера:

```yaml
services:
  kkal:
    # ...
    networks: [caddy]
networks:
  caddy:
    external: true   # имя сети, в которой работает ваш Caddy
```

```
kkal.example.com {
    reverse_proxy kkal:3000
}
```

После правки выполните `docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile` (или перезапустите контейнер Caddy).

Если перед сервером стоит ещё один прокси (nginx и т. п.), он должен передавать заголовки `Host` и `X-Forwarded-Proto`, а `BASE_URL` должен совпадать с адресом, который видят люди.

## Вход и пользователи

**Как входят люди.** На экране входа человек вводит почту и получает код из 6 цифр. Код действует 10 минут. Новый код можно запросить раз в минуту и не больше 5 раз в час. После 5 неверных попыток код сгорает. С одного IP можно сделать не больше 20 запросов кода в час.

**Кто может войти.** Только существующие пользователи, приглашённые адреса и те, у кого есть действующая ссылка-приглашение. Открытой регистрации нет. Пока в системе нет ни одного пользователя, войти может только `ADMIN_EMAIL`. Если он не задан, первым войдёт кто угодно и станет администратором, поэтому задайте его до запуска.

**Управление (шестерёнка → «Люди», только для администраторов):**
- пригласить по почте: человеку придёт письмо со ссылкой на сайт, а в списке он висит как «ждёт первого входа», пока не войдёт;
- ссылка для мессенджера: кнопка «Ссылка для мессенджера» даёт одноразовую ссылку на 7 дней, «Многоразовая ссылка» — ссылку без срока и без ограничения числа людей. Человек открывает её, вводит свою почту, получает код и регистрируется. На телефоне сразу открывается меню «Поделиться». Ссылка показывается только при создании; в списке «Ссылки-приглашения» видно, сколько людей по ней пришло, и её можно отозвать. Многоразовую ссылку не выкладывайте в открытые чаты: по ней может зарегистрироваться любой;
- отозвать приглашение;
- сделать администратором или снять права;
- заблокировать: человек сразу выходит со всех устройств и больше не может получить код. Данные при этом сохраняются, разблокировать можно в любой момент.
- удалить: аккаунт, весь дневник и входы удаляются навсегда (подтверждение вторым нажатием). Человека потом можно пригласить заново — дневник начнётся с нуля.

Аккаунты, созданные раньше по ссылкам-приглашениям, могут привязать почту в «Настройки → Аккаунт».

**Без почты.** Ссылки входа тоже работают. Кнопка «Войти на другом устройстве» выдаёт ссылку на 15 минут, а консольные команды ниже создают ссылки-приглашения.

```bash
docker compose exec -u node kkal node dist/cli.js invite "Маша"           # обычный участник
docker compose exec -u node kkal node dist/cli.js invite "Саша" --admin   # администратор
docker compose exec -u node kkal node dist/cli.js users                    # список
docker compose exec -u node kkal node dist/cli.js login 2                  # ссылка входа для пользователя с id 2
```

## Настройки

Почти всё настраивается в самом приложении: шестерёнка в шапке, раздел виден только администраторам. Изменения применяются сразу, перезапуск не нужен.

| Раздел | Что внутри |
|---|---|
| Модель распознавания | API-ключ, модель, адрес API, «размышления» вкл/выкл, сколько ждать ответа, предел длины ответа, температура, дополнительные указания модели, доп. параметры запроса (JSON). Кнопка «Проверить» делает пробный запрос |
| Лимиты | распознаваний на человека в день, цель по калориям для новых участников |
| Почта | SMTP-сервер, порт, логин, пароль, отправитель. Кнопка «Отправить тестовое письмо» шлёт письмо на почту администратора |
| Сайт | публичный адрес (из него собираются ссылки в письмах), название |
| Вход | временный постоянный код для `ADMIN_EMAIL` |

У каждого поля подписано, откуда взято значение: «задано здесь», «из .env» или «по умолчанию». Порядок такой: значение из приложения, потом `.env`, потом значение по умолчанию. Кнопка «сбросить» возвращает значение из `.env` или умолчание.

Ключи и пароли работают только на запись. После сохранения их нельзя прочитать ни в интерфейсе, ни через API, видны только последние 4 символа. При этом в базе (`data/kkal.sqlite`) они хранятся в открытом виде, поэтому файл базы и его копии надо беречь.

Только в `.env` остаётся то, что нужно до запуска: `ADMIN_EMAIL`, `PORT`, `DB_PATH`. Переменные `BASE_URL`, `LLM_*`, `SMTP_*`, `DAILY_LIMIT`, `STATIC_LOGIN_CODE`, `APP_NAME` по-прежнему читаются из `.env` как запасные значения.

Если перед приложением стоит nginx, его `proxy_read_timeout` должен быть не меньше, чем «Ждать ответа» в настройках модели, плюс 30 секунд.

## Резервная копия

Все данные лежат в одном файле `data/kkal.sqlite`. Копировать его на ходу можно так:

```bash
docker compose exec -u node kkal node -e "require('better-sqlite3')('/app/data/kkal.sqlite').backup('/app/data/backup.sqlite').then(()=>console.log('ok'))"
```

## Обновление

Вручную:

```bash
git pull && docker compose up -d --build
```

**Кнопкой из приложения.** Один раз выполните на сервере в папке приложения:

```bash
sudo ./deploy/install-updater.sh
```

После этого в «Настройках» у администратора работает кнопка «Обновить из GitHub». Приложение само ничего не запускает: оно только кладёт файл-запрос в `data/updater/`. Системная служба `kkal-update.path` на сервере видит этот файл и запускает `deploy/update.sh`, который делает `git pull --ff-only` и `docker compose up -d --build`, а потом ждёт, пока новая версия ответит. Ход обновления и журнал видны прямо в карточке. Если сборка не удалась, остаётся работать прежняя версия.

`git pull` выполняется от владельца папки приложения, поэтому доступ к GitHub (ключ или токен для приватного репозитория) должен быть настроен у этого пользователя. Если на сервере есть свои правки в файлах из репозитория, обновление остановится и об этом будет написано в журнале. Отключить кнопку: `sudo ./deploy/install-updater.sh --remove`.

## API

Все маршруты, кроме `/api/auth/*`, `/i/:token` и `/healthz`, требуют cookie сессии.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth/request` | Отправить код на почту: `{email}` |
| POST | `/api/auth/verify` | Войти по коду: `{email, code}` (с сессией без почты — привязать почту) |
| GET | `/api/users` | Пользователи и ожидающие приглашения (админ) |
| PUT | `/api/users/:id` | `{disabled}`, `{isAdmin}` (админ) |
| DELETE | `/api/users/:id` | Удалить человека и все его данные (админ) |
| DELETE | `/api/invites/:email` | Отозвать приглашение (админ) |
| POST | `/api/join-links` | Ссылка для мессенджера: `{multi:false}` — одноразовая на 7 дней, `{multi:true}` — многоразовая без срока (админ) |
| DELETE | `/api/join-links/:id` | Отозвать ссылку (админ) |
| GET | `/api/auth/join?t=` | Проверить ссылку-приглашение; дальше `request`/`verify` с полем `join` |
| GET | `/i/:token` | Вход по одноразовой ссылке |
| GET / PUT | `/api/me` | Профиль, дневная цель, `{toilet}` — отметки туалета вкл/выкл |
| GET | `/api/export.xlsx?tz=` | Весь дневник в Excel (`tz` — смещение часового пояса браузера, мин) |
| GET | `/api/days?from=YYYY-MM-DD&to=YYYY-MM-DD` | Записи за период |
| PUT | `/api/days/:date` | Сохранить день целиком (`{entries:[…]}`) |
| POST | `/api/estimate` | Распознать еду: `{text, images:[dataURL], date}` → `{dishes, note}` |
| POST | `/api/login-link` | Ссылка для входа на другом устройстве |
| POST | `/api/invites` | Пригласить: `{email}` или ссылкой `{name}` (админ) |
| GET / PUT | `/api/settings` | Все настройки (админ): `{values:{ключ: значение | null}}`; секреты только на запись |
| POST | `/api/settings/test-mail` | Тестовое письмо администратору |
| POST | `/api/settings/test` | Проверить связь с моделью |
| GET / POST | `/api/update` | Состояние и журнал обновления / запросить обновление из git (админ) |
| POST | `/api/logout` | Выход |
